### 프로젝트 요약

전자현미경(SEM)으로 촬영한 반도체 웨이퍼 결함 이미지 4,591장을 학습해 6종 결함을
자동 분류하는 모델을 만들고, 이 모델을 생산 라인의 자동 판정에 투입할 수 있는지를
측정했다. 분류 정확도는 97.97%를 얻었으나, 같은 테스트셋에서 픽셀 통계 8개와 얕은
결정트리만으로도 93.61%가 나왔다. 쏠린 데이터에서 정확도가 성능을 가린다는 뜻이다.

더 중요한 문제는 모델이 틀릴 때도 확신한다는 점이었다. 오답의 평균 신뢰도는 0.897로
정답의 0.995와 크게 다르지 않았고, 오답 14건 중 9건이 신뢰도 0.9를 넘었다. 설계 당시
설정한 재검토 임계값은 테스트 689장 중 한 건도 걸러내지 못했다. softmax 신뢰도로는
자동 판정을 걸 수 없다는 결론이다.

마지막 특징 공간의 마할라노비스 거리로 신뢰도를 다시 정의하자 선택적 예측 성능이
크게 개선되었다(AURC 0.0196 → 0.0006). 이 기준으로는 검사의 94.5%를 오류 0건으로
자동 통과시킬 수 있다. 다만 임계값이 검증셋에서 시험셋으로 그대로 옮겨가지 않았고,
그 원인과 해결 방향까지를 본 보고서의 결과로 제출한다.

이와 함께, 결함 로그 텍스트와 이미지를 함께 사용해 원인 후보를 좁히는 추론 엔진을
LLM 없이 구현했다. 로그 포맷을 흡수하는 어댑터 층을 분리해, 다른 팹에 적용할 때
수정 범위가 어댑터 한 층에 머물도록 설계했다.

## 1. 과제의 개요

### 가. 배경 및 필요성

1) 웨이퍼 결함 판정이 아직 숙련 검사자의 육안에 의존한다. 검사자마다 기준이 달라지고
   처리 속도가 생산 속도를 따라가지 못한다.

2) 결함 종류별 데이터가 극심하게 불균형하다. 본 과제가 사용한 공개 데이터셋에서도
   한 종류가 전체의 87%(4,008장)를 차지하고 가장 적은 종류는 4장뿐이다. 이 상태에서는
   전체 정확도가 높게 나와도 희귀 결함을 전혀 잡지 못할 수 있어, 정확도만으로 성능을
   판단할 수 없다.

3) GPU 서버를 전제한 검사 시스템은 장비 비용과 전력 때문에 생산 라인마다 배치하기
   어렵다. 저전력 가속기에서 동작하는 경량 모델이 필요하다.

4) 범용 비전 LLM은 두 가지 이유로 공정 장비에 넣을 수 없다. 첫째, 웨이퍼 이미지는
   공정 데이터여서 외부 API로 반출할 수 없는 경우가 많다. 둘째, 수십억 개 이상의
   파라미터와 외부 서버를 전제하므로 장비 옆에서의 실시간 판정에 맞지 않는다.

### 나. 목표

1) SEM 웨이퍼 이미지를 입력받아 6종 결함 중 하나로 분류하는 모델을 학습한다.

2) 모델이 자신의 오류 가능성을 스스로 판별하게 하여, 사람 확인 없이 자동 통과시켜도
   되는 구간과 재검토로 넘겨야 하는 구간을 분리한다.

3) 결함 로그 텍스트와 이미지를 함께 사용해 원인 후보를 좁히는 추론 엔진을 LLM 없이
   구현하고, 공정 장비에 탑재 가능한 수준의 지연·메모리를 확보한다.

4) 학습된 모델을 INT8로 양자화해 FPGA에 이식할 수 있도록 인계 패키지를 구성하고,
   CPU·GPU·FPGA를 같은 기준으로 비교할 수 있는 측정 체계를 만든다.

### 다. 개발 내용

1) 재현 가능한 학습 파이프라인 — 설정 파일 하나로 전처리 · 학습 · 평가가 동일하게
   재현된다(난수 고정). 분할 목록, 성적표, 혼동 행렬이 모두 파일로 남는다.

2) 신뢰도 보정 및 선택적 예측 모듈 — temperature scaling, ECE, MSP · Energy ·
   Mahalanobis 신뢰도 점수, risk-coverage 곡선, Clopper-Pearson 상한 기반 임계값 선택.

3) 원인 추론 엔진 — 어댑터 / 엔진 / 지식베이스 3층 구조. LLM 미사용.

4) 양자화 인계 패키지 — float32 가중치, 저장소 없이 모델을 복원하는 독립 정의 코드,
   INT8 보정용 이미지 300장, 전처리 규격, 테스트셋과 float 모델 로짓.

## 2. 과제의 내용

### 가. 설계 및 개발의 내용

#### 1) 개념 설계 (구조 설계)

전체 시스템은 세 개의 층으로 나뉜다. 층을 나눈 목적은 **다른 회사·다른 장비에 적용할 때
수정 범위를 한 층으로 묶는 것**이다.

| 층 | 역할 | 교체 여부 |
| --- | --- | --- |
| ① 어댑터 | 원본 로그(KLARF 결함 레코드, SECS/GEM 알람, 자체 CSV)를 공통 자료구조 `DefectEvent`로 정규화 | 회사마다 교체 |
| ② 엔진 | `DefectEvent` + 이미지 → 원인 순위와 근거 산출 | 고정 |
| ③ 지식베이스 | 원인 × (스텝, 장비, 결함 형태, 로그 키워드, 조치) 표 | 공정마다 작성 |

엔진이 원본 로그를 직접 참조하지 못하도록 자료구조로 차단했다. 이 제약이 있어야
"로그 처리 방식만 맞추면 그대로 투입 가능"이라는 설계 목표가 코드 수준에서 보장된다.

**AI 기술의 적용 위치**는 두 군데다.
- 이미지 분류기(ResNet18)가 결함 형태로부터 클래스 확률을 산출해 원인 후보를 축소한다.
- 분류기의 마지막 특징 공간에서 계산한 마할라노비스 거리가 "학습 분포 밖" 입력을
  판별해, 엔진이 추론을 포기하고 사람에게 넘기는 관문 역할을 한다.

원인 순위 산출 자체에는 학습 모델을 쓰지 않는다. 원인 후보가 고정된 문서 집합이므로
역색인 검색(BM25)으로 충분하며, 이것이 장비 탑재 가능성의 근거다.

> 시스템 구성도는 별첨의 「시스템 아키텍처」 도식 참조.

#### 2) 상세 설계 (기능 설계)

**가) 데이터 파이프라인**
- 입력 480×480 JPG → 224×224 리사이즈 → ImageNet 평균·표준편차로 정규화
- 증강: 좌우반전, 회전 15°, 밝기·대비 변화
- 분할: train 3,213 / val 689 / test 689 (계층 추출, 표본 부족 시 비계층으로 폴백)
- 불균형 대응: 클래스 역빈도 가중 샘플링(가중치 1/n_c)

**나) 분류 모델**
- ResNet18, ImageNet 사전학습 가중치에서 전이학습, 출력층 6클래스로 교체
- AdamW(lr 1e-3, weight decay 1e-4), cosine 스케줄러, batch 32, 5 epoch
- 파라미터 11,179,590개 / float32 44.7MB / INT8 환산 11.2MB

**다) 신뢰도 보정과 선택적 예측**
- 보정: 검증셋 NLL을 최소화하는 온도 T로 로짓 스케일 조정
- 신뢰도 점수 비교: MSP(최대 softmax), Energy(-logsumexp), Mahalanobis(특징 공간
  거리, 클래스 공통 공분산). 표본이 2장뿐인 클래스가 있어 클래스별 공분산은 세울 수
  없으므로 공통 공분산에 정칙화를 적용했다.
- 운영점 선택: 검증셋 선택적 위험의 Clopper-Pearson 상한이 목표치 이하가 되는
  임계값을 고른다. 표본이 적을수록 상한이 느슨해져 임계값이 자동으로 보수적으로 잡힌다.

**라) 원인 추론 엔진**
세 단계로 후보를 좁힌다.
1. 하드 필터 — 스텝·장비가 일치하지 않는 원인을 제거 (감소폭이 가장 크다)
2. 이미지 지지도 — 분류기의 클래스 확률로, 해당 결함 형태를 만들 수 없는 원인을 제거
3. BM25 텍스트 점수 — 로그 문구와 겹치는 원인을 상위로 올림

최종 점수는 세 항의 가중합이며, 각 결과에 **어떤 토큰이 매칭되었는지**를 함께 반환해
엔지니어가 추천 근거를 확인할 수 있게 했다. 한국어는 형태소 분석기 대신 공백 분리와
글자 2-gram을 함께 색인해 조사·어미 변화를 흡수했다(외부 의존성 제거 목적).

**마) 어댑터 계약**
`DefectEvent` = 결함 ID, 로트/웨이퍼 ID, 이미지 경로, 스텝, 장비, 레시피,
결함 형상(좌표·크기·면적), 자유 텍스트, 원본 보존 필드.
KLARF 유사 포맷용과 일반 CSV용 어댑터 두 개를 참조 구현으로 제공한다.

### 다. 최종 결과물

#### 1) 분류 성능 (테스트셋 689장)

| 지표 | 값 |
| --- | --- |
| Accuracy | 97.97% |
| macro-F1 | 0.756 |
| Precision (macro) | 0.729 |
| Recall (macro) | 0.826 |
| 검증셋 최고 정확도 | 99.27% |

오분류는 14건이며, 이 중 class_3 12건이 class_1로 분류되었고 표본이 1장뿐인
class_5는 맞히지 못했다.

#### 2) 기준선 대비 기여 (동일 테스트셋)

| 기준선 | Accuracy | macro-F1 |
| --- | --- | --- |
| 최빈 클래스로 고정 | 87.37% | 0.155 |
| 픽셀 통계 8개 + 깊이 4 결정트리 | 93.61% | 0.425 |
| ResNet18 (본 과제) | 97.97% | 0.756 |

정확도 차이는 4.4%p에 불과하지만 macro-F1은 0.425에서 0.756으로 올랐다. 본 과제가
실제로 개선한 것은 **희귀 결함에 대한 성능**이며, 정확도 단독 지표로는 이 차이가
드러나지 않는다.

| MSP + temperature | 0.01960 | 0.0% |

| **Mahalanobis (특징 공간)** | **0.00060** | **94.5%** |

softmax 계열 점수로는 오류를 하나도 통과시키지 않으려면 사실상 전량을 사람이 확인해야
한다. 특징 공간 거리로 바꾸면 선택적 예측 성능이 약 32배 개선되며, 검사의 94.5%를
오류 0건으로 자동 통과시킬 수 있다.

### 마. 개선 방안

1) **운영 임계값이 검증셋에서 시험셋으로 전이되지 않는다.** 오류율 1% 이하를 95%
   신뢰도로 보증하는 임계값을 검증셋에서 선택했으나, 시험셋 실제 오류율은 1.2~1.6%로
   목표를 넘었다. 검증셋 689장에 희귀 클래스가 1장씩만 포함되어 운영점을 고정할 표본이
   부족한 것이 원인이다. 희귀 클래스 데이터 확보, 교차검증 기반 임계값 선택, 또는
   선택 편향을 보정하는 절차가 필요하다.

2) **희귀 클래스는 분류 문제로 풀 수 없다.** class_5는 전체 4장으로, 어떤 학습
   기법으로도 분류기가 일반화할 표본이 아니다. 분류가 아니라 이상 탐지로 재정의하고,
   정상 분포에서 벗어난 정도로 판단해 사람에게 넘기는 방향이 타당하다.

3) **FPGA 구간이 미실측이다.** CPU 20.2ms와 GPU 7.9ms는 확보했으나 INT8 양자화 후
   정확도 변화와 FPGA 지연·전력은 측정하지 못했다. 인계 패키지에 float 로짓을 포함한
   것은 양자화 전후를 샘플 단위로 대조하기 위한 것이며, 보드 확보 후 즉시 비교 가능하다.

4) **원인 추론 엔진이 가상 로그 기반이다.** 사용한 공개 데이터셋에는 공정 로그와 원인
   라벨이 없어, 공개 표준(KLARF, SECS/GEM)의 구조를 참고해 가상 로그를 생성하고
   엔진 로직을 검증했다. 이는 엔진의 논리적 타당성을 확인한 것이며 실제 팹에서의 성능은
   아니다. 실제 로그 확보 시 어댑터 교체만으로 검증을 이어갈 수 있도록 설계했다.

## 3. 과제의 향후 계획

### 가. 활용 방안

1) **검사 공정 내 자동 판정 보조.** SEM 촬영 직후 검사 장비가 산출한 이미지를 그대로
   입력받아 결함 종류와 원인 후보를 제시하고, 신뢰도가 낮은 건은 재검토 대기열로
   분리한다. 판정 결과는 결함 ID 기준 레코드로 산출되어 기존 수율관리 시스템에 병합할
   수 있다.

2) **타 팹·타 장비로의 확장.** 어댑터 한 층만 교체하면 로그 포맷이 다른 환경에도
   적용할 수 있도록 설계했다. 참조 어댑터 두 종을 함께 제공한다.

3) **타 공정 이미지로의 재학습.** 전처리 규격과 학습 파이프라인이 설정 파일로
   분리되어 있어, 다른 공정의 검사 이미지로 동일 절차를 재현할 수 있다.

4) **교육·연구 자료.** 정확도만으로 모델을 판단할 때 생기는 문제와 그 측정 방법을
   실제 데이터로 보인 사례로 활용할 수 있다.

### 나. 기대 효과

1) **검사 품질의 일관성.** 검사자마다 달라지던 판정 기준을 단일 모델로 통일하고,
   모델이 확신하지 못하는 건만 사람에게 남긴다. 판정 이력이 기록으로 축적된다.

2) **비용·전력 절감.** GPU 서버 없이 라인 단위 저전력 추론이 가능하며, 한 장을 더
   판정하는 한계비용이 사실상 0이다. 설비 증설 없이 검사 지점을 늘릴 수 있다.

3) **도입 비용의 구조적 절감.** 신규 적용 시 수정 범위가 어댑터 한 층으로 제한되어,
   사이트마다 시스템을 새로 구축할 필요가 없다.

4) **자동화 판단 근거 확보.** 어느 구간까지 사람 없이 맡길 수 있는지를 수치로 제시해,
   도입 여부를 감으로 결정하지 않아도 된다.
